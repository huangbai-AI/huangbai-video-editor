# 剪映可编辑工程：批量制作与原生验证

核查日期：2026-11-04。适用于用户要求真实剪映工程、分段粗剪和复合片段；不强制所有 B-roll 请求都建整片工程。版本和格式会变化，以下实测不能自动推广到其他机器。

## 先选择能完成任务的入口

| 入口 | 已知能力／依据 | 边界与选择 |
|---|---|---|
| `jianying-tool` 0.5.0 CLI | 本机已用 `probe`、`create`、`split-segment`、`doctor`；生成工程在 Mac 剪映 11.7.0 打开成功 | 本次未发现通用复合片段命令；不能据此声称全部编辑能力已验证。安装包指向的 `lhwget/auto_edit` 本轮 GitHub 返回 404，公开源码可用性未确认 |
| [jianying-local-mcp](https://github.com/Capricornus-joe/jianying-local-mcp) 0.3.0 | 面向 Mac，批量建稿、多轨、字幕、关键帧；`batch_edit` 多步合成一个新版本。已读源码并在本机直接调用核心函数验证 | 只修改它管理的工程；不回收剪映手改状态，不读加密稿，不自动导出；场景复合尚未集成为通用工具。不能把示范成片当成所有功能都可调用 |
| [JianYing-AutoEdit-MCP](https://github.com/Mal-Suen/JianYing-AutoEdit-MCP) | README 的 `build_from_storyboard` 能按分镜一次组装视频、音频、字幕、转场，先校验 | 文档的可用成稿／导出主要针对 Windows；Mac 目录探测待验证。未在本机试用，不替代已工作的 Mac 路线 |
| [pyJianYingDraft](https://github.com/GuanYixuan/pyJianYingDraft) 0.3.1 | 草稿生成底层库，可用于定制批量组装；相邻片段推荐共用结束边界避免时间舍入重叠 | 0.3.0 的自定义加载接口不等于自带解密器。模板保留复合片段也不等于可以自由创建、修改复合片段 |

源码依据：local-mcp 提交 `f47f907e7bc15e68082238e50ca5964c50b2f559`，重点读 `server.py`、`core.py`、`batch.py`、`docs/tools.md`、`docs/case-study.md`、`docs/performance.md`。[pyJianYingDraft 发行说明](https://github.com/GuanYixuan/pyJianYingDraft/releases)明确说明加载接口边界。

local-mcp 本机小样：100 条合成文字片段，改一条正文、统一字号、加粗三步只创建一个新修订；原工程文件哈希不变；加入无效步骤后未写入目标工程。验证的是 Python 核心批处理，不是已连接 MCP、剪映原生画面或导出。仓库自己的速度基准不包含启动应用、审看、渲染，不能宣传整片提速若干倍。

遇到现有工具不支持：先查官方仓库、源码、问题记录和社区实现，优先匹配系统、版本与交付形式。仅输出 MP4 的“视频合并”、只支持 Windows DLL 的读取器、仅控制素材库的 Hub，都不能替代 Mac 上可继续编辑的真实工程。不要为尝试路线覆盖正式稿。

## 推荐工作顺序

1. 读取最新脚本和备注，列出素材清单、台词锚点、章边界、源入点与时长。用户指定来源优先；已有作品用原素材，真实操作录真实界面，概念才做说明动画。打开网页不等于素材已经提取或录完。
2. 检查原素材画幅、帧率、声音、镜像状态。保存原件，建立工作副本／可追溯引用；现场文件名可帮助匹配，但仍须核对内容。时间线帧率与源帧率分开记录。
3. 先在隔离小样里验证新稿可打开、复合片段可内部修改、保存重开仍生效。满足用户要“先验证”的顺序，不等全片制作后才发现不支持。
4. 制作所需素材并核对实际输出尺寸；用外部剪辑清单保存素材路径、稳定片段 ID、章节、源／时间线范围、轨道、缩放位置、声音处理。口播删停顿、删磕巴必须核对语义和声音连接，不仅凭静音阈值自动删。
5. 批量建稿或多步修改：先预检，再一次写新版本；先剪裁和排序，后加动画。local-mcp 的 `create_draft` 不登记剪映首页；`publish_draft` 才登记且要求应用完全退出，遵循实际工具接口。不要每加一个片段就进剪映保存一次。
6. 完整保留可重建的源计划、未被剪映保存过的源稿和素材。将单独副本交剪映打开；在原生界面完成尚无可靠接口的复合整理、命名和微调。手改会与外部计划分叉，应记录差异；重建的新版本不能无声丢掉手改。
7. 按用户要求每个 part／阶段一个复合片段，内部保留口播与辅助素材独立轨道。不要把整章提前压成一条 MP4 冒充可编辑复合片段。最后连续视听、检查章边界和原声、导出并独立复检。

local-mcp 批处理示例（已有管理工程，正式写入前先将 `dry_run` 设为 `true`）：

```json
{
  "name": "rough-v1",
  "new_name": "rough-v2",
  "steps": [
    {"action":"edit","operations":[{"op":"update","id":"title1","changes":{"text":"第一招 多多益善"}}]},
    {"action":"style_subtitles","track":"报幕","style":{"font_size":42,"color":"#FFFFFF"}},
    {"action":"features","clip_ids":["title1"],"features":{"text_style":{"bold":true}}}
  ],
  "dry_run": false
}
```

这里的原生文字可改字；已生成 PNG 的文字只能更换图片。不能为了方便批处理，擅自把用户要的贴纸美术替换成普通字幕。

## 保存后哪个文件才可信

Mac 剪映 11.7.0 本次实测：新建时主文件为明文；应用保存后，根目录和活动 `Timelines` 中的 `draft_info.json`、根目录 `draft_meta_info.json` 变为编码内容。根 `draft_content.json` 及 `subdraft` 下仍能读的文件可能只是旧状态，未含后来切分和报幕。

- 不以“还能解析 JSON”作为最新状态的证明。结合修改时间、活动时间线、片段数量和原生界面交叉核实。
- 多时间线先确认 `timeline_layout.json` 中活动项；不要同时盲改所有副本或用旧明文覆盖新状态。
- 当前工具不支持读回时，继续在剪映里编辑，或从保存的源计划生成新版本；说明两条路径的差异，不宣称能无损接续所有手改。
- 用户说忽略旧稿、新建，就停止旧工程路线。结构备份若排除了媒体，不得称为可独立迁移的完整工程包。

## 少走弯路的原生界面操作

以下入口在本机验证过；每次先看当前界面和键位，不能保存固定屏幕坐标跨会话盲点。

- 应用实际路径为 `/Applications/VideoFusion-macOS.app`；中文应用名无法匹配时使用已核实路径。
- 时间线片段右键→新建复合片段（子草稿）；双击进入，顶部返回箭头回主线。本机 Final Cut Pro X 键位下是 Option+G，新机器先核实。
- 重命名入口：素材→导入→子草稿，缩略图右键重命名，名称同步主线；不要反复在错误的右键菜单找。
- 本机分割是 Cmd+B。每次分割／删除前确认选中的是目标轨，特别是上方报幕不能误删下方口播。
- 导入文件时先等“前往文件夹”对话框出现，再填写路径并确认；过早输入可能沿用旧路径。核对选中文件后再导入。
- 素材缩略图被选中／预览不代表已加到时间线。本次右下角添加入口有效；拖拽未成功就改用明确入口，随后核对轨道和片段数。
- 浮动播放器遮住主窗口时，先还原布局；不能据此误判工程不能打开。
- 窗口和弹窗变化后重新观察；已失效的坐标／入口不反复试点。

## 验收必须区分的层级

| 结果 | 证据要求 |
|---|---|
| 工程已创建 | 实际工程路径和剪映打开结果 |
| 复合片段可编辑 | 进入内部，选中并改动一个独立素材，返回、保存、重开确认保留 |
| 报幕已加入 | 正确章节、独立轨、时长、下方口播连续；说明图片文字是否可改 |
| 素材已完成 | 实际文件、尺寸、时长、声音和对应脚本；不能只列计划 |
| 整片完成 | 所需素材全部接入、口播剪辑、片头片尾按要求处理、连续视听和最终导出验收 |

音量表跳动只说明有音频信号，不能替代听音。生成提示词写 2K／4K、工程设置为 4K，都不证明素材本身有该分辨率。静态图片不称动画；可独立移动的图片不称逐字可编辑文字；未做完整视听或独立复检时明确标待检。

## 本轮全片实作补充：可靠复合与真实录屏

- 2026-11-04，Mac剪映11.7.0，完整素材稿157.62秒、五章36条辅助画面：CLI先写平铺口播与B-roll两轨，再在剪映逐章框选、Option+G建立原生复合，保存重开可编辑，最终原生导出成功。
- 直接仿造已有subdraft wrapper、复制内部草稿以及补path，曾能显示/播放，但不能可靠进入内部。不得把“JSON含复合结构”当成可编辑验证；本机默认采用平铺后原生分章路线。
- 框选前把播放头移出拖选起点附近。靠近播放头拖动可能只移动播放头，旧选区不变，Option+G会把上一章反复套娃。先截图确认所有目标白框再建复合，误操作及时撤销并核对五章。
- 素材库会残留撤销操作或旧尝试产生的子草稿；验收看主线、内部独立轨和保存重开结果。旧明文subdraft文件未必含新切分。
- Screen Studio可能录到底层旧页面而不是Ego任务页面；先录短样，实际打开看画面。窗口标题/工具成功返回不能证明录对。本次弃用错误样本，改录目标页CDP连续帧。
- CDP帧按实际timestamp排序并保存源时间信息；静止页面可能低频出帧。统一编码30fps不等于原生30fps录制。保留连续原录与竖屏剪辑副本。
- Ardot技能“去试试”可能hover后出现；先hover再点可见项，不强点隐藏同名元素。上传和启用后要真实调用并确认结果。
- 录到生成等待时，保留原录，成片剪到实际结果展示；输入栏及字号位置参数应给近景。长文快滚只证明多个结果，不能当观众读完正文。
- 作品图必须对照角色、动作与口播。兔子拍风景不能配兔子冲刺、乌龟休闲的旧图；可改说明动画，但明确不冒充软件生成结果。
- 输入延展提示词但未提交，随后展示旧作品，应说明是已有成果展示，不能称新生成过程。演示修改完成后恢复原设计，核验字号和坐标。
- 导出视频应核对实际分辨率、时长、音轨，并与预览区别记录。解码成功、播放到ended与真正连续视听是不同验证，不自动宣称发布验收完成。
